# 12 · 案例：分布式限流网关

> 考察重点：限流算法、分布式一致性、多级限流、维度。

---

## 一、需求

**功能需求**
- 在 API 网关层对所有入口请求做限流。
- 支持按用户 ID、IP、接口、租户多种维度。
- 被限流返回 429 + Retry-After。
- 规则可动态配置，不用重启。

**非功能需求**
- 限流判断本身 P99 < 5ms（不能因为限流把请求拖慢）。
- 全局限流要准（不能因为多机导致配额翻倍）。
- 限流组件挂了不能把主链路搞挂（fail-open）。

---

## 二、规模估算

- 入口总 QPS 10 万。
- 限流规则上千条。
- 限流判断本身要在 5ms 内完成，不能成为瓶颈。

---

## 三、高层设计

```
  Client
    ↓
  网关集群（无状态，多实例）
    ↓ 每个请求都要做限流判断
  ┌─────────────────────────────┐
  │  本地限流：Guava/Sentinel 单机桶 │  ← 第一道，挡突发
  └─────────────┬───────────────┘
                ↓ 本地通过
  ┌─────────────────────────────┐
  │  分布式限流：Redis + Lua     │  ← 第二道，全局限额
  └─────────────┬───────────────┘
                ↓ 全局限额也通过
            转发到后端服务
                ↓
  规则配置中心（Nacos/Apollo）→ 推送到网关本地
```

---

## 四、核心组件细节

### 4.1 多级限流
- **第一级：单机限流**。每台网关本机用令牌桶（Guava RateLimiter），限制单台机器每秒最多处理 N 个请求。挡的是本机突发，不依赖网络。
- **第二级：全局限流**。查 Redis，按 `user:{userId}` 或 `api:/login` 维度扣配额。
- 为什么要两级？如果只做全局限流，每个请求都要打 Redis，Redis 挂了就全站不可用；本地限流先扛住大部分流量，Redis 只做精细配额。

### 4.2 Redis + Lua 实现
- 全局限流用令牌桶或滑动窗口。
- Lua 脚本保证「读-判断-写」原子：
  ```lua
  -- KEYS[1] = 限流 key
  -- ARGV[1] = 窗口大小 ms
  -- ARGV[2] = 最大请求数
  local current = redis.call('INCR', KEYS[1])
  if current == 1 then
    redis.call('PEXPIRE', KEYS[1], ARGV[1])
  end
  if current > tonumber(ARGV[2]) then
    return 0  -- 被限流
  end
  return 1  -- 通过
  ```
- Redis 单线程执行 Lua，天然原子。

### 4.3 维度
- **按用户 ID**：防单个用户刷爆。登录用户用 user_id，未登录用 device_id。
- **按 IP**：防爬虫，但 NAT 出口会误伤，阈值要宽。
- **按接口**：登录接口单独限流（防爆破），搜索接口单独限流（防滥用）。
- **按租户**：SaaS 平台每个租户一个配额。

### 4.4 动态规则
- 规则存在配置中心（Nacos/Apollo）。
- 网关启动时全量拉一次，后续监听变更推送。
- 本地内存维护规则表，限流判断不查远端。

### 4.5 失败处理
- Redis 超时/挂了：fail-open（默认放行），不能因为限流组件把全站搞挂。
- 同时告警，人工介入。
- 本地限流永远在线，即使 Redis 挂了本机也能自保。

### 4.6 被限流的响应
- 返回 HTTP 429 Too Many Requests。
- Header 带 `Retry-After: 60` 告诉客户端等多久重试。
- 前端展示友好提示，不要直接报错页。

---

## 五、权衡

| 选择 | 放弃了什么 | 为什么 |
|------|-----------|--------|
| 两级限流 | 复杂 | 兼顾性能和全局准确 |
| Redis Lua | 引入 Redis 依赖 | 全局限流必须中心化 |
| fail-open | Redis 挂时全局限流失效 | 可用性优先于限流 |
| 本地内存规则 | 规则更新有秒级延迟 | 限流判断不能查远端 |

## 六、常见追问点

- **Q：固定窗口为什么有临界突刺？**
  A：窗口边界 59 秒和 01 秒各打满，实际 1 秒内通过 2 倍阈值。用滑动窗口或令牌桶解决。
- **Q：Redis 集群挂了？**
  A：fail-open 放行 + 告警；本机 Sentinel 限流还能挡一部分。
- **Q：怎么防止恶意用户换 IP 刷？**
  A：结合账号维度限流，不单独靠 IP。
- **Q：限流阈值怎么定？**
  A：压测单机极限，按 80% 设阈值；上线后观察实际流量调整。
- **Q：和熔断有什么区别？**
  A：限流是挡入口流量保护自己；熔断是发现下游挂了停止调用保护下游。两个都要有。
