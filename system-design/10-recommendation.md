# 10 · 案例：推荐系统

> 考察重点：召回 + 排序两段式、特征工程、在线/离线、冷启动。

---

## 一、需求

**功能需求**
- 首页 Feed 个性化推荐：给不同用户推不同内容。
- 「猜你喜欢」商品推荐。
- 相关推荐：看完一篇文章/一个商品，推相似的。

**非功能需求**
- 推荐接口 P99 < 200ms（首屏不能等）。
- 推荐结果要实时反映用户最近行为（刚看完篮球，别马上推美妆）。
- 每天亿级用户、百亿级候选物料。

---

## 二、规模估算

- DAU 1 亿，人均刷 20 次推荐流。
- 推荐请求 QPS ≈ 1 亿 × 20 / 86400 ≈ 2300，峰值 10 倍 ≈ 2.3 万。
- 候选物料库千万级。
- 每次推荐从千万候选里挑 20 条返回。

---

## 三、高层设计

```
  离线阶段（小时/天级）：
    用户行为日志 → 特征工程 → 训练模型 → 产出用户向量/物品向量
                                    ↓
                              写入 Redis / 向量库

  在线阶段（实时，每次请求）：
    用户请求
       ↓
  ┌──────────────────────────────────────────┐
  │  召回层（多路召回，从千万→千级）            │
  │   - 协同过滤召回（和你相似的人喜欢什么）      │
  │   - 向量召回（你的兴趣向量和物品向量近邻）    │
  │   - 热门召回（全站热门兜底）                │
  │   - 标签召回（你关注的标签）                 │
  │   → 合并去重，得到 ~1000 候选              │
  └──────────────────────────────────────────┘
       ↓
  ┌──────────────────────────────────────────┐
  │  粗排（轻量模型，1000→200）                │
  └──────────────────────────────────────────┘
       ↓
  ┌──────────────────────────────────────────┐
  │  精排（重模型，200→20）                    │
  │   特征：用户画像 + 物品特征 + 上下文（时间/地点）│
  │   模型：DeepFM / DIN / 自研                 │
  └──────────────────────────────────────────┘
       ↓
  ┌──────────────────────────────────────────┐
  │  重排：业务规则过滤（去重、多样性、打散、运营干预）│
  └──────────────────────────────────────────┘
       ↓
    返回 20 条给用户
       ↓
  用户行为（点击/滑动/停留）→ 实时特征 → 下次请求影响推荐
```

---

## 四、核心组件细节

### 4.1 召回层
- 目标是**快**，从亿级物料里粗筛出几百上千个候选。
- 多路召回并行：
  - **向量召回**：用户兴趣向量（由最近行为加权）和物品向量算余弦相似度，取 Top N。用 Faiss/Milvus 这类向量检索库。
  - **协同过滤**：「看过 A 的人也看过 B」的物品相似矩阵。
  - **热门召回**：全网 24 小时热门榜，保证兜底内容不冷场。
  - **标签召回**：用户关注的标签下最新内容。
- 多路结果合并去重，得到 ~1000 个候选。

### 4.2 粗排和精排
- **粗排**：用简单模型（逻辑回归、浅层 DNN）快速给 1000 个候选打分，砍到 200。
- **精排**：复杂模型（DeepFM/DIN/多目标），综合预估点击率、点赞率、停留时长。
- 精排慢，所以只喂 200 个候选；粗排快，所以喂 1000 个。

### 4.3 特征
- 用户特征：年龄、性别、历史点击、关注标签、活跃度。
- 物品特征：类别、作者、热度、发布时间。
- 上下文特征：当前时间、地理位置、设备、网络。
- 在线特征从 Redis 取（毫秒级），离线特征从 Hive/Spark 算好写进特征库。

### 4.4 实时反馈
- 用户点了一条 → 发 MQ → 实时特征服务更新「用户最近兴趣向量」。
- 下次请求时召回已经受这次点击影响，延迟秒级。

### 4.5 冷启动
- **新用户**：没行为数据，先用注册时选的兴趣标签 + 热门内容兜底。
- **新物品**：没被点过，用内容标签先塞给一小部分用户做探索（exploration），积累数据后再进主推荐。
- **探索与利用（EE）**：偶尔给用户推一些他没试过的类别，避免信息茧房。

---

## 五、权衡

| 选择 | 放弃了什么 | 为什么 |
|------|-----------|--------|
| 两段式召回+精排 | 架构复杂 | 一次从亿级排到 20 条太慢 |
| 向量召回 | 需要训练 embedding | 比规则召回效果好很多 |
| 实时特征 | 系统复杂度 | 用户兴趣变化快，离线特征跟不上 |
| 强制探索 | 短期点击率下降 | 避免信息茧房和内容陈旧 |

## 六、常见追问点

- **Q：推荐接口 200ms 够吗？**
  A：召回多路并行 <50ms，粗排 <30ms，精排 200 条 <100ms，总 <200ms 可控。
- **Q：怎么衡量推荐效果？**
  A：在线指标：点击率、停留时长、次留；离线指标：AUC、NDCG。
- **Q：模型多久训练一次？**
  A：天级全量训练 + 小时级增量更新；实时行为走在线特征补充。
- **Q：用户反馈「怎么老推重复的」？**
  A：重排层加去重（同一作者/类别打散）+ 近期已读过滤。
- **Q：推荐要不要做 A/B？**
  A：必须，新模型先小流量实验，指标显著正向再全量。
